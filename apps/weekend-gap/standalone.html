Operating calendar overrides

Dated closures, delayed reopenings, extended windows, and scheduled capacity changes. Each override names a half-open hour range inside the horizon; later entries win per field. Ranges outside the horizon are rejected.

Scheduled funding tranches

Reserve cash added before a named hour settles, with the cost of securing it tracked as an expense. Costs never reduce the reserve. Tranches outside the horizon are rejected.

    Each modeled hour is tagged with the single limitingGate value at the start of the interval. Closed issuer, bank or payout gates are named first. This is a count of observations, not a ranking of which change would raise settlement.

    Blockers can overlap. Counts describe observed constraints while backlog remains, not how much a single change would improve settlement. Queue exposure sums end-of-hour backlog across 72 one-hour intervals.

    About and method

    A constrained operating-window model

    At each hour, synthetic redemption demand enters a queue. Settlement can occur only when issuer redemption, bank settlement and Australian AUD payout windows are all open. The hourly capacity is the smallest of issuer throughput, available FX depth, payout throughput and remaining AUD reserve. An optional Monday public-holiday flag keeps those windows closed on Monday, the same way Sunday is already closed. An optional Saturday public-holiday flag treats Saturday like Sunday.

    What it shows

    How a closed payout chain can create queued AUD demand and lower immediately redeemable capacity even while onchain transfers continue.

    What it does not show

    It does not model real issuers, legal redemption rights, reserve attestations, counterparties, exchange order books, credit risk, token price discovery or operational incidents.

    How to use it

    Edit the synthetic fields, choose a preset, scrub the timeline, or export a scenario. Shared links contain only the editable scenario in the URL hash.

    Detailed formulas and limits are included in this standalone simulator.

    Weekend Gap uses only synthetic, editable assumptions. AUD values are illustrative.

    This is a synthetic liquidity study

    Weekend Gap is an educational liquidity simulator. Every assumption is invented and editable. It is not live market data, issuer information, or financial advice.

    Three gates must overlap before queued demand can settle: issuer redemption, bank settlement, and Australian AUD payout. Saturday and Sunday keep those gates closed. An optional Monday holiday treats Monday the same way. An optional Saturday holiday records Saturday as a Sunday-like public holiday.

    The clock runs from Friday 15:00 to Monday 15:00 in abstract local time. Demand can still join the queue while the payout chain is closed.
